# Mekanism Magic 1.0.6.29（未发布开发版）

## 魔源宝石无催化配方与AE样板

修复原版没有基座催化材料的灌注配方仍被JEI和AE转移强制加入催化标识的问题。
不是修改Ars原配方，也不把这些配方改成免费生产。

| 原版配方ID | 原料 | 输出 | Source |
| --- | --- | --- | ---: |
| ars_nouveau:imbuement_amethyst | 紫水晶碎片 | 魔源宝石×1 | 500 |
| ars_nouveau:imbuement_lapis | 青金石标签 | 魔源宝石×1 | 500 |
| ars_nouveau:imbuement_amethyst_block | 紫水晶块 | 魔源宝石块×1 | 2000 |

- 依据原`getPedestalItems().isEmpty()`统一处理，不按这三个物品ID硬编码例外。JEI无催化行不再画标识输入格，AE转移仅写入真实原料。
- 新的普通一输入/一输出样板仅在唯一、准确匹配当前无催化配方时接入精确灌注解码；其它普通AE加工样板不被随意接管。
- 兼容旧的合法虚拟标识样板；标识从规划与实际投递中剔除。显式标记损坏、冲突、签名过期时拒绝，不回退成要求玩家供应内部标识/NBT的普通样板。
- ME工厂无催化任务跳过催化目录选择，但仍验证宿主和配方；不会因目录里没有零催化虚拟条目而拒绝下单。有催化任务仍使用原来的验证和成功后提交选择流程。
- 普通灌注机、普通工厂、Extras工厂对已标记无催化任务按精确ID执行；同原料存在其它催化/无催化配方时，不能被当前选择抢走。整批剩余原料保留内部配方信息，不仅保护第一件。
- 新投递附带完整配方语义签名，原料匹配只看去掉内部字段的副本，真实槽负责扣量。输出来自原配方，不复制输入标记；旧仅ID标记仍按当前合法配方兼容。
- 语义签名补入原先遗漏的输出数量，改产量、输出组件、原料或Source后，旧已派发签名不能继续按改变后的配方生成新结果。
- 原生AE直连灌注机仍保留稳定配方定义，无催化配方继续正常广告；无催化派发也附带精确ID，不依赖同原料配方的排序。
- JEI数据更新时同步刷新催化标识制作页与灌注页，按完整内容复用/替换条目；退出JEI时释放新增缓存引用。

## 使用与范围

替换测试包并重启后重新下单。新写样板不再含无用催化标识；旧合法样板仍兼容，若网络尚有失败的旧任务，可取消后重新下单或取出重插样板。

内部路由字段只保留在尚未消耗的原料批次，整批加工完自然消失，成品不带这些字段。手动取出处理中余料仍可能带有该批次字段；本轮不额外改写原Mek/Extras手动提取槽或全局物品组件。

不改变原Source消耗、FE档位、工厂并行数、魔法灌注附魔装置配方或已有物品模型。已完成的`.28`包保留：`2082B86F4C1BF944FD6BF6CCF4D60606BE3C5F6835A5269BF5FAD9C5996E44C0`。

```text
gradlew runEnergyGameTestServer -Pmekanism_magic.ars_runtime=true --no-daemon
gradlew check assemble validatePackagedIntegrations -Pmekanism_magic.require_full_integrations=true --no-daemon
```
