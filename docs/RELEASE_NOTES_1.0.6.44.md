# Mekanism Magic 1.0.6.44 — 修复右侧按钮重叠

本次按用户确认修复主项目，不修改 `Mekanism Magic V5 Test` 独立分支。
保留 `.43` 取消通用粉笔 JEI 替代显示的修改与 `.42` 的启动修复。

## 原因与改动

- MekE 3.0.6 的样板按钮实际占用右侧 `y=62..87`，粉笔／辞典模块原本从
  `y=80` 开始，导致 8 像素纵向重叠。两者改用共享的第一模块行 `y=90`。
- 秘仪演算核心的保留物品模块（末影之眼）占用 `y=118..143`，原生红石按钮
  固定在 `y=137..162`，导致 7 像素重叠。红石按钮现在在界面初始化／尺寸变化后
  贴齐当前机器面板底部；208 像素高界面为 `y=179..204`。
- 166 像素高的标准机器仍使用原生 `y=137`，不改变普通紧凑界面的排位。
- 辞典、粉笔、催化库及保留物品模块共用行间距定义，为可选 ME 样板按钮保留原生行。
  催化库和保留模块的现有行号、展开库存坐标没有变化。
- 只处理实现 `MagicThemedScreen` 的本模组界面，不移动 Mekanism 或其他模组的按钮。
  使用原生 `GuiElement.move` 同时移动绘制位置和点击区域；不会改变按钮动作。

没有修改槽位数量、物品存储、配方、加工逻辑、注册 ID 或机器名称。
此次新增右侧布局类、客户端初始化事件，并实际修改模块按钮构造代码，验证后
从有效主项目基线 `.43` 递增一次到 `.44`；测试／打包次数不是递增依据。

## 验证

- IDEA 主项目连接正常；新增事件和粉笔标签检查无错误，Java 编译通过。
- `testMachineSidebar`：220 组布局，使用真实原生 tab 检查可点击区域、
  1–4 倍坐标缩放、重复对齐不漂移、尺寸变化、模块回调及样板行预留。
- 实际调用 `ScreenEvent.Init.Post` 处理器，确认本模组界面移动红石按钮，
  非本模组界面保持原位；确认客户端事件订阅与 MekE 本地字节码的实际行号。
- `testRetainedModules`：6,944 组库存面板、55,552 次库槽边界检查及界面接线通过。
- `testMachineTitles`：47 对双语标题和 7 个共享页头通过；55 个机器契约通过。
- 完整 `check -x jar -x validatePackagedIntegrations` 通过。验证阶段排除打包依赖，
  保护已有同号 JAR；版本更新后再单独打包和核验适配内容。

本轮没有重启用户客户端、修改玩家存档或执行游戏内截图验收；验证是实际控件／
事件处理器的离线测试，不应称为整合包游玩实测。未发布或上传。
