# Mekanism Magic 1.0.6.46 — 微缩法阵材料匹配修复

这是 1.0.6fix 内容范围上的本地开发修复包，未发布到 GitHub/CurseForge。
主开发树同步源码修复和版本号，但不从包含未完成内容的主开发树打包。
保留 34 台已发布机器、37 条获准资源配方和法阵捕获；
不包含未完成的自然灵气、禁忌、新魔法资源存储元件或接口。

## 修复

- 使用原生法阵的 StateMatcher 规则生成材料候选，不再把当前预览画面当作唯一配方。
- 原生蜡烛标签与中央仪式碗标签内的合法物品均可参与制作。
- 按固定预览时间 0 获取代表物品，不改变共享法阵的世界绑定；查看全典或预览不会改变配方要求。
- JEI 同时列出合法替代材料，轮换时保留正确数量；配方重载比较包含候选列表。
- 使用有容量约束的匹配器扣除材料，支持分散槽位、混合种类及重叠候选，不重复扣料。
- 未知或无法读取的法阵不生成“只需染料”的残缺配方。
- 材料候选按配方版本缓存，数据包同步或客户端配方刷新后失效；不在每次加工中遍历注册表。
- 保留对带额外物品组件的保护，不静默吞掉容器中保存的数据。
- 普通献祭之碗不会被当作中央仪式碗。染料、粉笔和材料数量仍须满足配方。
- 之前的五 tick 启动等待修复、彩虹/虚空通用粉笔能力、粉笔不消耗及法阵捕获保持不变。
  没有重新添加用户要求取消的彩虹/虚空粉笔 JEI 轮换显示。

## 验证

针对截图配方独立构造输入，不从待测机器的配方生成器读取投料：

- 34 种原生标签蜡烛，逐种实际制作。
- 6 种中央仪式碗，搭配分散槽位的混合蜡烛实际制作。
- 各种替代材料的 JEI 列表与原生标签集合、数量一致。
- 缺少蜡烛、混入冲突染料、错误的普通献祭碗、缺少粉笔均不能制作，输入不消耗。
- 全典预览时间 0/20 下，代表材料、替代物品列表、数量与排序一致。
- 既有 18 法阵 × 普通/彩虹/虚空粉笔 × 连续两次加工，以及 16 粉笔槽、漏斗补料等回归继续通过。
