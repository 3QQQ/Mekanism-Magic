# Mekanism Magic 1.0.6.41 — 灌注连续加工与配方切换修复

## 修复

- 普通灌注机的缓存键纳入当前催化物选择。原料不变时，切换实体标识物、
  虚拟标识物或清除选择，都不再沿用旧配方或旧的“未找到配方”缓存。
- 原生及 Extras 灌注工厂的缓存有效性同时校验原料、当前催化物和配方目录版本。
  同一种魔源宝石切换火焰／水之精华等配方后，能够重新匹配并连续加工。
- 工厂先判断配方身份，再判断魔源是否足够。已经失效的旧配方会清理进度，
  不会在缺少魔源时永久停留为忙碌状态；有效配方缺少魔源时仍暂停等待补给。
- 不改变配方、输出、魔源收费、电力规则或存档字段；保留无催化物配方的
  精确样板标记和自动化跨配方投料的占用保护。

## 验证

- 修改前新增的五项复现测试全部失败：普通机出错产物、两类工厂卡旧缓存、
  无空闲 tick 的连续批次无法切换，以及清除选择后继续使用旧配方。
- 修改后游戏运行矩阵 71/71 通过。其中新增八项测试覆盖三类机器的实体／虚拟
  选择切换、连续三件加工、火→水→火批次、清除选择和缺魔源场景，
  并通过普通机原生 AE 提供器及两类工厂真实 MekE 样板提供器连续投料。
- IDEA 后台编译无错误；完整 `check` 通过，包括机器契约、双语标题、
  灌注 JEI 合约、现有自动化保护及包内适配校验。
- 最终 `assemble validatePackagedIntegrations -Pmekanism_magic.require_full_integrations=true`
  通过。JAR 内 664 个主类与当前编译结果逐一一致，不含测试类。
  相比原 `.40`，仅四个已修复源码对应的主类／内部类及版本元数据改变，
  没有新增、丢失或改变其他包内资源。

上述运行时代码变更完成并验证后，开发版本从 `.40` 只递增一次到 `.41`。
没有修改其他机器界面，没有关闭或重启用户客户端，也没有发布或上传。
