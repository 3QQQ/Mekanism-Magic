# Mekanism Magic 1.0.6.3（未发布开发版）

本轮修复神秘学仪式引擎产物与 JEI 样板组件不同，导致 AE 无法判定完成或继续合成
下一阶矿工的问题。原生矿工的实际产物、JEI 输出与后续材料统一使用默认显示灵名和
已初始化的采矿参数；已有耐久、附魔、自定义名称、显式采矿参数及其他组件保留。
这里的保留指规范化所处理的物品栈，本轮未改变原生矿工升阶配方继承附魔等组件的规则。

9 种原生命名物品改为复制配方结果，不再继承激活书的随机灵名：知识石板、
`ender_satchel`、`satchel`、灌注镐、维度矩阵、两种仪式袋、存储遥控及
`iesnium_butcher_knife`。此改动仅限本模组机器，Occultism 原版仪式与绑定书合成不变。

上述机器 JEI 配方使用未绑定之书。先将魔灵全典放入仪式引擎的全典槽；全典不消耗，
也不作为样板材料。对应已绑定之书仍可手动投入。JEI 已补充设置说明。

更新后从机器 JEI 重新编码并替换相关处理样板，包括下一阶矿工的输入；取消旧 AE
挂单，核对已产出或退回的材料后重新下单。旧库存与存档 NBT 不会自动改写，AE/MekE
仍严格匹配实际组件，不清除耐久、附魔、物品内容或绑定数据。

状态：未发布。联合 GameTest 59/59 通过，包含 4 项新增回归：真实 AE CPU 连续
完成 5 次订单（重复低阶制作、使用库存升阶、递归两阶制作），不同绑定名实际产物一致，
功能 NBT 不被合并，以及 9 种原生命名产物与 JEI、样板声明一致。`check`、47 项机器
资源契约与打包检查均通过。

独立 CPU 订单按 CPU 空闲、原链接未取消、请求量归零及精确产物数量回网判定成功；
