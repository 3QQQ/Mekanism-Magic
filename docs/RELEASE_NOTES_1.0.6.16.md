# Mekanism Magic 1.0.6.16（未发布开发版）

通过 Blockbench MCP 完成自然灵气机器系列模型，按用户要求后台运行，不占用鼠标键盘。

- 7 台独立机器均完成新结构：FE灵气转换器、燃料灵气发生器、灵气场接口、自然祭坛
  处理机、自然献祭处理机、树木仪式处理机、动物生成处理机。
- 自然祭坛工厂使用新的三工位主结构，基础至无限八档保留原版等级灯及其颜色、UV
  和发光数据；Mekanism Extras 两种高阶动态灯保留原始动画纹理。
- 深灰机身、浅灰金属导轨、金色连接件、自然绿状态条组成统一材质语言；不同功能
  不套用同一种上部轮廓。
- 保持所有模型在单个方块内。现有 Java 工作动画、法阵、配方物品和实体的坐标不改，
  静态工作盘保持留空，避免额外叠出不动的完整法阵。
- 没有改机器处理逻辑、配方、消耗、存储容量、管道速度或原版/附属的等级灯文件。
- 通过实际 BB 预览修正外露共面纹理交叠，再以旋转面片相交及遮挡检查复核。

可编辑工程和原生 Java 导出保存在 `assets/blockbench/nature_precision_v1/`，共
16 份工程（含一份工厂共用主结构），对应 15 个游戏方块。材质完整内嵌；工程说明见
[建模目录 README](../assets/blockbench/nature_precision_v1/README.md)。旧 Ars/神秘学工程保留。

## 验证

`node tools/validate_nature_precision_models.mjs --details` 已通过：

- 16 份 BB 工程和 Java 导出与游戏模型的几何、旋转、UV、贴图引用一致；
- 旋转后的顶点均在 `[0,16]` 内，无 mesh、退化方块或退化 UV；
- 16 个工厂等级灯状态保留原版几何、纹理、UV 与发光数据；
- 法阵旋转范围、物品移动路径、动物实体空间均不被新结构遮挡；
- 外露共面冲突 **0**，完全被实体遮挡的内部接触面单独计数。

本轮已做 Blockbench 实际多视角预览，未启动用户游戏客户端，不声称已做游戏内实机
视觉验收。没有通过桌面截图或按键操纵用户正在使用的其他应用。

`check assemble validatePackagedIntegrations`（要求完整可选集成）通过，49 个机器契约
通过。JAR 内八个更新的主结构模型逐字节匹配源码；工厂的八档共用主结构展开工程
