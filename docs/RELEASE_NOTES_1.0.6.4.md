# Mekanism Magic 1.0.6.4（未发布开发版）

本轮修复仪式演算核心与奥术附魔机的动态产物预览和 AE 样板编码：
机器 JEI 根据显示的实际输入计算产物，AE 转移时再次核对完整组件和数量。
耐久、附魔、容器内容、实体 UUID、职业与绑定目的地仍属于物品身份；
不会通过清理库存 NBT 或全局忽略组件来让订单完成。

神秘学的 4 条修复配方与 2 条复活配方，在未指定实际激活物品时只显示说明图标。
`repair_icon` 与 `resurrect_icon` 不再作为 JEI 的 OUTPUT，也不能编码为 AE 产物。
将鼠标放在实际工具或保存实体数据的灵魂碎片上，按 JEI“显示用途”键（默认 `U`），
进入本模组的神秘仪式分类，即可看到该物品的精确结果。修复只恢复耐久，保留其余
组件；复活保留实体数据。3 条升级配方按实际主料生成结果，保留内容和绑定等数据，
并正确使用目标物品的最大耐久。

需要绑定书的召唤与职业胶囊配方，机器 JEI 默认使用未绑定之书，并显示不消耗的魔灵全典催化剂。
编码后，先将全典放入仪式演算核心的全典槽。若从已有名称的绑定书查看用途，预览与
实际胶囊会保留该名称，以及随胶囊保存的召唤之书组件。实体落地时的职业初始化、
归属和召唤之书绑定行为继续生效。

奥术附魔机新增同名的专属 JEI 分类，原版 Ars 的物理附魔装置分类保持原样。
专属分类使用 Ars 的实际匹配与 `assemble` 结果，可保留原有附魔、护甲升级状态、
卷轴目的地等组件。默认试剂只有通过实际配方校验时才显示可编码产物；从实际试剂
按 `U` 查看时，以该物品的状态为准。等级或状态不符时给出说明，不会悄悄退回默认
试剂。需要玩家或物理装置上下文、机器无法计算的结果也不会被当作确定产物编码。

无序材料中的卷轴复制优先选择携带绑定数据的卷轴作为试剂，空白卷轴作为复制材料，
不再受槽位顺序影响。如果两张绑定卷轴会产生不同目的地的结果，机器拒绝启动。

新增 AE 转移逻辑只编码可见的消耗输入和经复核匹配的实际输出。全典、仪式选择器及
说明图标不进入消耗材料。终端槽位不足、缺少实体数据、配方重载后显示内容失效或
产物不匹配时，会提示原因并拒绝此次转移。奥术附魔机同时启用已有的 MekE
上下文校验：广播和投料都检查完整输入与输出；缺少完整声明的自动化入口不接受
处理订单，旧智能队列沿用网络退款与恢复缓存机制。

更新后请从对应的机器 JEI 分类重新编码并替换受影响样板。旧挂单仍期待旧组件，
需要先核对已产出及退回的材料，再取消并重新下单。已有库存和存档物品不自动改写。
一张样板描述一组精确输入与输出；它不能无条件接受所有不同 NBT，否则会丢失
附魔、内容或绑定等有效状态。
