# 1.0.6.60 — Mek 原生界面样板

按用户选择的 Mekanism 工业风，先完成两台实际界面样板：灵气凝聚器与赫菲斯托斯锻造台。
其余自然灵气、禁忌及其它系列界面暂不铺开，等待样板确认。

## 客户端改动

- 两台样板显式使用 Mekanism 原生机壳、物品槽、按钮与配置窗口，不再叠加本附属的魔法背景。
  这两台不显示附属的深浅主题切换按钮；其它机器的主题、设置和贴图解析保持原样。
- 增加凹入式深色仪表，常驻短标签、数值及单位，完整说明仍在悬停提示中。
  Forge 的内部等级和四种精华可直接辨识，灵魂精华统一为紫色提示条。
- 标题仍使用共享坐标、滚动与状态预留空间，保持服务器提供的标题及玩家自定义名称。
- 增强器保留物侧栏匹配原生灰壳；原始槽绑定、开关、缩放重建和关闭后恢复不变。
- 不修改任何服务器机器、菜单槽位、槽索引、配方、资源传输、生产逻辑或存档键。
- 尊重用户资源包对 Mekanism 原命名空间的覆盖，不以样板强制绕过用户资源包。

本轮相对 `1.0.6.59` 的实质改动是客户端界面渲染和样板皮肤分派，完成验证后只递增一次到 `.60`。
没有发布正式版本、创建标签或修改历史开发包。

## 验证

- 机器界面、标题、侧栏、保留物与 52 个机器契约测试通过。
- 新增两样板范围隔离、双语标签/单位、长值边界、完整提示、填充边界及主题隔离回归。
- 隔离真实客户端：原生资源中文、原生资源英文、终端资源包中文三轮各 9 张截图，均有新鲜 PASS 报告。
- GUI scale 2/3 均验收；Forge 额外验收侧面配置、增强器侧栏展开/关闭与原槽恢复。
- 原生验收明确清除隔离目录中的文件资源包选择，不改用户实际运行目录的配置或资源包文件。
- 最终 `check`、`assemble`、全量 `validatePackagedIntegrations` 全部通过；样板类已打包，验收/自测类未进入模组 JAR。
- 本地报告：`build/mek-ui-samples-native-zh.json`、`build/mek-ui-samples-native-en.json`、
  `build/mek-ui-samples-pack-zh.json`；构建与检查日志为 `build/mek-ui-samples-*.log`。

没有改变仓库默认依赖版本或历史构建。
